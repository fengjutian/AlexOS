# 应用清单

普通桌面应用使用 `manifest.json`。以下是一个带 Node 服务的最小示例：

```json
{
  "schemaVersion": 1,
  "id": "com.example.notes",
  "name": "Notes",
  "version": "0.1.0",
  "frontend": { "entry": "frontend/index.html" },
  "backend": {
    "runtime": "node",
    "entry": "backend/index.js",
    "mode": "service",
    "healthCheck": { "path": "/health", "timeoutMs": 3000 }
  },
  "permissions": [
    { "name": "runtime.invoke" },
    { "name": "storage" },
    { "name": "window.manage" }
  ]
}
```

## 关键字段

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定的应用身份，使用反向域名格式 |
| `version` | 语义化版本号 |
| `frontend.entry` | 包内 HTML 入口，不能逃逸应用目录 |
| `frontend.build` | 可选前端构建命令与参数 |
| `backend` | 可选 Node.js 后端配置 |
| `permissions` | 应用能够请求的能力上限 |

## 后端模式

- `rpc`：通过 stdin/stdout JSON Lines 调用，适合方法型后端。
- `service`：运行长期 HTTP/WebSocket 服务，由 Runtime 分配环回端口并进行健康检查。

## 权限原则

只声明功能实际需要的权限。清单声明不是自动授权：用户仍可以允许、拒绝或撤销权限。

多服务、资源配额、Native Worker、MCP 与 Agent 应用可使用 v2 `app.yaml`；两个清单不能同时存在于同一个包中。
